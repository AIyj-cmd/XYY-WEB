# B2B 企业官网设计参考

> 本文档用于约束企业官网、B2B 落地页、产品服务页、解决方案页、案例页、FAQ 页等页面的设计与改造过程。
> 仅在明确的页面设计或视觉改造任务中按需阅读，不作为日常开发前置条件。
> **本文件的核心目标不是统一所有页面的外观，而是保证每个页面先具备清晰的信息结构、阅读路径和业务转化逻辑。**

---

## 0. 使用优先级

执行任何页面设计、重构或优化任务时，必须按以下顺序处理：

1. 页面业务目标与信息结构
2. 用户阅读路径与排版布局
3. 主次层级、内容顺序与认知负担
4. 呼吸感，以及需要做减法还是加法
5. 视觉风格、组件表现与品牌统一
6. 交互、特效与动画
7. 响应式、无障碍、性能与验收

**禁止跳过前四步，直接修改颜色、卡片、渐变、动效或视觉特效。**

若页面结构和阅读路径尚未成立，不得用动画、卡片、阴影或装饰掩盖问题。

---

# 1. 页面设计前的需求审计

## 1.1 先明确页面唯一主任务

每个页面必须先回答：

- 这是什么页面？
- 主要给谁看？
- 用户为什么会进入这一页？
- 用户进入后最需要知道什么？
- 用户看完后应该做什么？
- 页面唯一主转化动作是什么？

一页可以包含多个模块，但只能有一个核心任务。

示例：

- 首页：建立品牌认知、证明能力、引导咨询
- 产品服务页：帮助客户判断需要哪项服务
- 产品详情页：解释某项服务如何解决问题
- 案例页：证明方案真实有效，降低决策风险
- FAQ 页：消除客户疑问，承接搜索与转化
- 联系页：降低沟通门槛，完成线索提交

## 1.2 建立信息优先级

页面内容必须分成以下层级：

### 一级信息：必须第一时间看到

- 页面是什么
- 核心价值
- 用户能得到什么
- 主要行动入口

### 二级信息：帮助用户继续判断

- 适用场景
- 核心能力
- 服务范围
- 差异化优势

### 三级信息：建立信任

- 数据
- 客户案例
- 真实图片
- 流程
- 系统能力
- 资质与标准

### 四级信息：补充与消除顾虑

- FAQ
- 费用说明
- 数据口径
- 条件限制
- 行业来源

不得让三级、四级信息抢占一级信息的视觉重点。

---

# 2. 用户阅读路径

## 2.1 页面必须形成连续叙事

常见 B2B 页面阅读路径：

```text
用户问题
→ 解决方案
→ 核心能力
→ 可信证据
→ 实施方式
→ 客户案例
→ 常见疑问
→ 转化行动
```

不能只按公司内部组织结构排列内容。

错误示例：

```text
公司介绍
→ 企业文化
→ 仓库面积
→ 系统模块
→ 新闻动态
→ 联系方式
```

正确示例：

```text
客户遇到什么问题
→ 我们如何解决
→ 为什么相信我们
→ 具体怎么合作
→ 下一步做什么
```

## 2.2 每一屏只完成一个主要任务

每个大区块必须有明确职责。

例如：

- Hero：说明页面定位与核心价值
- 服务选择：帮助客户选择
- 产品能力：解释能解决什么
- 数据模块：证明承接能力
- 流程模块：解释如何执行
- 案例模块：证明实际效果
- FAQ：处理顾虑
- CTA：推动下一步行动

禁止一屏同时承担“介绍、选择、证明、流程、案例、咨询”多项任务。

# 3. 排版与布局规则

## 3.1 先分组，再排版

页面内容必须先形成信息组：

- 标题组
- 说明组
- 数据组
- 能力组
- 图片组
- 行动组

同一组内部距离小，不同组之间距离大。

判断标准：

- 用户能否一眼看出哪些内容属于同一组
- 标题是否明确控制下面的内容
- 页面留白是否在表达层级，而不是随机空白

## 3.2 标题层级必须清楚

建议层级：

```text
栏目标签 / Eyebrow
页面主标题 / H1
区块标题 / H2
模块标题 / H3
正文
辅助说明
```

要求：

- 页面只保留一个 H1
- H1 表达页面核心价值，不堆品牌词
- H2 说明每一屏解决的问题
- H3 用于能力、场景、案例等子模块
- 正文不能与标题字号接近
- 辅助说明不能比正文更抢眼

禁止所有内容使用相似字号和字重。

## 3.3 对齐规则

页面必须建立稳定的对齐线：

- 主内容最大宽度统一
- 标题、正文、按钮、卡片遵循相同栅格
- 左右分栏必须有明确比例
- 图片与文字应在视觉中心或顶部形成关系
- 不允许每个区块自行设置不同宽度

建议桌面端：

- 内容最大宽度：1200–1360px
- 正文阅读宽度：620–760px
- 区块左右边距：32–64px
- 大区块上下间距：96–144px
- 内容组间距：24–48px

## 3.4 阅读成本检查

必须检查：

- 标题是否需要读两遍才能理解
- 一段正文是否包含过多信息
- 用户是否需要阅读全部卡片才能知道选什么
- 选项文字长度是否差异过大
- 是否存在重复说明
- 是否存在三个以上并列重点
- 文字是否过小、过淡、过宽
- 是否出现无意义的大面积空白

# 4. 页面结构模板

这些模板是信息结构参考，不要求所有页面长得一样。

## 4.1 Hero

Hero 只负责：

- 页面身份
- 核心价值
- 简短解释
- 主次 CTA
- 必要的信任证明

推荐结构：

```text
栏目标签
主标题
一句解释
主按钮 + 次按钮
轻量数据或信任信息
```

禁止：

- Hero 同时放完整流程、多个产品导航和大量数据
- 两条完整导航栏
- 四个以上按钮
- 大量卡片覆盖背景图
- 背景图只是装饰，与业务无关

## 4.2 服务选择器

用户从问题进入，而不是从产品名称进入。

推荐结构：

```text
左侧：当前遇到的问题
右侧：推荐方案详情
```

右侧方案至少包含：

- 推荐方案名称
- 解决结果
- 3项核心能力
- 1–2项可信数据
- 适用场景
- 详情 CTA

## 4.3 产品能力模块

结构统一，但表现形式可以不同：

- 仓储：真实场景大图 + 数据
- 质检：流程 + 分级 + 修复能力
- 数字化：系统截图 + 功能标注
- 智能寄件：主界面 + 辅助界面 + 路由能力

不要让所有产品都使用相同的左图右文或四张卡片。

## 4.4 案例模块

必须形成：

```text
客户类型
→ 原有问题
→ 使用方案
→ 结果或规模
→ 查看案例
```

禁止只放 Logo 墙。

## 4.5 FAQ

首页只保留核心问题，默认折叠。

回答结构：

```text
先直接回答
→ 再补关键证据
→ 最后说明条件或口径
```

完整 FAQ 应进入独立页面。

# 5. 卡片使用规则

## 5.1 什么时候使用卡片

适合：

- 并列选择
- 服务组合
- 方案对比
- 独立案例
- 明确的信息单元

不适合：

- 所有内容
- 长段正文
- 流程说明
- 页面导航
- 仅为填补空白

## 5.2 卡片不能完全同构

同一组卡片可以统一骨架，但应根据内容加入不同的业务识别：

- 图形
- 流程
- 数据
- 场景
- 截图
- 状态

禁止整页反复使用：

```text
图标
标题
四行文字
按钮
```

## 5.3 卡片数量

- 单屏推荐 3–4 张
- 超过 4 张应考虑分组、横向滚动、筛选或列表
- 卡片高度必须由内容结构控制，不得出现大量无意义空白
- 卡片间距与内边距必须统一

---

# 6. 呼吸感、减法与加法

## 6.1 呼吸感不是“越空越高级”

有效留白用于：

- 分隔信息组
- 建立主次
- 缓冲高密度内容
- 强化视觉中心

无效留白表现为：

- 内容漂浮
- 左右关系断裂
- 页面很空但不易阅读
- 信息之间没有归属

## 6.2 减法判断

只有以下情况才删除：

- 信息重复
- 与页面主任务无关
- 抢占核心重点
- 用户不需要在当前阶段看到
- 内容没有证据或无法解释
- 视觉元素不承担信息功能

## 6.3 加法判断

只有以下情况才增加：

- 帮助用户理解
- 建立内容关系
- 补充可信证据
- 提供下一步行动
- 让真实图片或系统截图承担业务表达
- 解决页面缺少视觉锚点的问题

不得因为“页面看起来空”就增加卡片、数据或装饰。

---

# 7. 图片与视觉内容

优先级：

1. 真实业务照片
2. 真实系统截图
3. 真实照片 + 系统界面组合
4. 定制示意图
5. 通用素材
6. AI 概念图

要求：

- 图片必须对应当前模块内容
- 统一色温、比例、圆角和清晰度
- 系统截图应裁掉浏览器无关内容
- 一张真实截图可以通过放大、裁切、局部标注提升表现
- 不为了数量生成虚假系统界面
- 图片中的标注必须帮助理解，不得重复文字内容

---

# 8. 色彩与背景

## 8.1 背景控制

长页面建议主要使用：

- 白色
- 浅灰蓝
- 少量深色 CTA

深色背景适合：

- Hero 局部遮罩
- 强调区
- 最终 CTA
- 页脚

不适合：

- 长正文
- 复杂流程
- 多组数据
- 连续多个产品区块

## 8.2 颜色职责

- 深蓝：品牌、标题、可信度
- 亮蓝：链接、状态、辅助强调
- 橙色：主 CTA、关键数据
- 灰蓝：正文、分割线、背景

一个颜色只能承担稳定职责，不得在不同页面随意变化。

---

# 9. 导航与页面内导航

- 全站主导航保持唯一
- 不允许主导航下面再出现第二条完整横向导航
- 页面内导航应采用小型悬浮、锚点、侧栏或横向滑动
- 当前状态必须清楚
- 页面内导航不应抢 Hero 主标题
- 移动端必须重新设计，不得直接压缩桌面导航

---

# 10. 交互与动效

只有结构、排版和内容层级通过后，才允许加入动效。

## 10.1 推荐动效

- 标题向上轻微渐入
- 图片裁切展开
- 数据递增
- 流程线绘制
- 卡片悬停上移 4–6px
- 箭头向右移动
- 标签展开
- 图片轻微缩放

## 10.2 禁止动效

- 持续漂浮
- 大量发光
- 粒子背景
- 鼠标跟随
- 所有文字逐字出现
- 强烈视差
- 循环闪烁
- 为动画延迟正文展示

动画必须：

- 200–500ms 为主
- 一次触发，不循环
- 尊重 `prefers-reduced-motion`
- 不影响移动端性能
- 不成为理解内容的必要条件

---

# 11. 响应式与移动端

移动端不是桌面端缩小版。

必须重新处理：

- 多列改为单列或横向滑动
- 左右分栏改为顺序内容
- 时间线改为纵向
- 图片热点改为标签或手风琴
- 截图拼贴改为单图轮播
- 悬浮导航改为横向滚动或折叠
- 不依赖 hover 展示重要信息
- 悬浮咨询按钮不得遮挡 CTA 和正文

关键宽度检查：

- 360px
- 390px
- 430px
- 768px
- 1024px
- 1366px
- 1440px

---

# 12. 无障碍与性能

## 无障碍

- 正文对比度足够
- 点击目标建议不小于 44px
- 键盘可访问
- 弹窗支持 Esc 关闭
- 焦点状态可见
- 图片有合理替代文本
- 装饰元素使用 `aria-hidden`
- 不用颜色作为唯一状态提示

## 性能

- 图片优先 WebP / AVIF
- 设置宽高或 `aspect-ratio`
- 首屏资源优先加载
- 非首屏图片延迟加载
- 不为简单动效引入重型库
- 防止布局跳动
- 移动端关闭非必要动画

---

# 13. 禁止项

执行页面改造时，禁止：

- 未审计业务目标就直接改视觉
- 未确认内容顺序就添加卡片
- 用大量深色背景制造“高级感”
- 所有模块统一成四卡或六卡
- 同一屏出现多个主标题
- 一段正文塞入多个业务主题
- 数据、产品、流程和导航混在一个 Hero
- 为填空增加无证据数据
- 使用与业务不符的 AI 图片
- 擅自修改数据库、接口或业务口径
- 擅自删除现有内容
- 为统一风格而破坏页面任务
- 在没有移动端方案时只完成桌面端
- 直接输出超长开发提示词并一次性大改全站

---

# 14. 页面审查输出格式

每次审查页面时，必须按以下顺序输出：

## 1. 页面任务

- 这页给谁看
- 要传达什么
- 唯一主转化是什么

## 2. 当前信息结构

列出当前区块顺序，并判断是否合理。

## 3. 用户阅读路径

说明用户第一眼、第二眼和最终行动分别是什么。

## 4. 排版与布局问题

检查：

- 主次
- 标题层级
- 对齐
- 顺序
- 认知负担
- 重复信息
- 内容分组

## 5. 加减判断

分别列出：

- 应删除或弱化的内容
- 应增加或强化的关系
- 应保留不动的结构

## 6. 视觉表现

结构确认后，再建议：

- 图片
- 卡片
- 配色
- 背景
- 圆角
- 图形

## 7. 动效与交互

最后给出克制的动效方案。

## 8. 响应式与验收

列出移动端、交互、性能和无障碍检查。

---

# 15. 给 Codex 的执行约束

执行页面改造前必须：

1. 阅读本文件
2. 只读分析当前页面代码
3. 输出页面任务、现有结构和问题
4. 给出改造范围
5. 等待确认后再修改复杂页面
6. 分阶段修改，每次只处理一个页面或一个区块
7. 保持现有接口、数据和路由兼容
8. 不修改与当前页面无关的文件
9. 完成后进行桌面端与移动端自检
10. 输出变更记录和未解决问题

复杂页面必须拆成：

```text
阶段一：信息结构与布局
阶段二：视觉系统与组件
阶段三：交互与动效
阶段四：响应式、测试与验收
```

不得将四个阶段混合在一次大规模修改中。

# 16. 最终验收清单

## 5 秒理解

- 用户能否在 5 秒内知道页面做什么
- 是否知道该点击哪里
- 是否知道下一步能获得什么

## 结构

- 每一屏是否只有一个主要任务
- 标题是否控制对应内容
- 内容顺序是否符合客户决策
- 是否存在重复表达
- 是否存在三个以上并列重点

## 排版

- 对齐是否统一
- 字号层级是否明确
- 正文是否易读
- 内容组是否清楚
- 留白是否有效

## 业务

- 数据是否有资料依据
- 服务范围是否准确
- 时效和费用口径是否统一
- 图片是否为真实业务
- CTA 是否与页面目标一致

## 交互

- 点击状态是否明确
- 移动端是否可用
- 动画是否影响阅读
- 悬浮按钮是否遮挡内容
- 弹窗、FAQ、导航是否正常

## 技术

- 页面无明显布局跳动
- 图片资源合理
- SEO 标题层级正确
- 结构化内容可被读取
- 不影响现有接口和功能

---

## 核心原则

> 先把页面讲清楚，再把页面排清楚；
> 先让用户看得懂，再让页面看起来好看；
> 先通过减法恢复秩序，再通过有意义的加法建立特色；
> 动画只能强化结构，不能替代结构。
