# CMS 本地隔离写入审计报告（2026-08-20）

## 结论

本轮在本机创建了完全隔离的 PostgreSQL 数据库和 Directus 12.1.1 实例，并通过真实 Directus 后台完成文章与附件写入。没有修改测试站、主站、真实 CMS、真实数据库、权限或部署，也没有修改业务代码。

实际结果表明，问题不能全部交给部署侧：

1. 在正确的全新 PostgreSQL Schema 上，文章封面上传、选择、保存、重开回显均正常；测试站和主站的“选择封面无效”主要是远端 `news.cover_image` 半迁移造成的，而不是 Directus 新闻表单本身失效。
2. 全新本地环境的封面公开 URL 仍返回 403。仓库当前只同步业务内容集合的读取权限，没有建立 `directus_files`/资源公开交付策略，因此后台成功保存封面后，前台仍会断图。这一项需要仓库与部署共同处理。
3. `scripts/setup-cms.mjs` 无法在全新数据库直接完成初始化：Singleton Seed 固定查询 `date_created`、`user_created`、`user_updated`，但部分单例定义没有这些字段。为继续功能审计，本轮只在一次性本地数据库临时补了三个占位字段；这是一项可复现的仓库代码缺陷。
4. 文章可以在未填写 `published_at` 时切换为 Published；前台会把 `null` 格式化为 `1970年1月1日`。需要发布校验或前台空值处理。
5. 本地 `/admin/content/news/+` 能正常打开，文章完整生命周期也能走通，未复现远端“有时 new 页面打不开”。结合远端旧字段和异常 slug，当前更符合远端 Schema/数据状态不一致；仍需保留浏览器日志后进一步定位。

## 实际写入流程与结果

隔离环境：Directus 12.1.1、独立 PostgreSQL 数据库、本地 Astro SSR；所有测试记录均使用 `【CMS本地测试】` 或 `local-audit-` 前缀。

### 新闻和附件

- 打开 `/admin/content/news/+`：成功。
- 新建草稿并填写标题、slug、分类、摘要和富文本正文：成功。
- 从本地上传 PNG 一次性附件：成功，Directus 文件库显示尺寸、大小和 MIME 类型。
- 在文章中选择该附件作为 `cover_image` 并保存：成功。
- 返回列表再重开文章：封面 UUID、预览和文件信息均保持，证明 UUID 字段及文件关系在正确 Schema 上可用。
- 将文章切换为 Published 并保存：成功；本地 `/news` 与详情页均返回 200，标题、正文和封面 URL 均出现在 HTML 中。
- 匿名请求封面 `/assets/{uuid}`：返回 403，确认前台断图不是文章关系未保存，而是文件交付权限未建立。
- 将文章切回 Draft：成功；文章从 `/news` 消失，详情返回 302 到 `/news`。
- 从 Directus 后台删除文章：成功。
- 从 Directus 文件库删除一次性附件：成功。
- 清理后 API 复核：`news=0`、`directus_files=0`。

### FAQ 关系型内容

- 在本地 CMS 创建一条 Published FAQ，并关联到 `faq_pages.key=news`：成功。
- 本地 `/news` 返回 200，新增问题实际显示：成功。
- 删除测试 FAQ 后重新请求 `/news`：问题消失。
- 清理后 FAQ 总数恢复为初始化种子的 100 条。

## 已确认的责任归类

### 仓库需要修复或补验证

- 修复 Singleton Seed 对不存在元数据字段的固定查询，使全新数据库可以直接执行 `scripts/setup-cms.mjs`。
- 明确 Directus 文件的交付方案：匿名只读、受控代理或签名资源，并把真实 `/assets/{id}` HTTP 200 纳入验证；只验证 UUID/URL 拼接不够。
- 发布文章时要求有效 `published_at`，或前台对空发布日期采用安全回退，禁止显示 1970 年。
- 增加新闻 slug 的 trim、格式及规范化后唯一性检查；修复已确认的功能标题 Claim 插值遗漏。
- 增加真实本地 CMS 写入回归：新建、保存重开、封面、发布、取消发布、删除及附件清理。

### 部署/CMS 侧需要处理

- 分别备份测试站和主站数据库及附件。
- 将远端 `news.cover_image` 从当前 varchar/无关系状态迁移为 UUID，并建立 `news.cover_image -> directus_files.id` 关系；不能只重新发布 Web 包。
- 配置与仓库最终方案一致的文件读取/代理权限，并验证后台预览及公开封面 URL 均返回 200。
- 清理带首尾空白的新闻 slug，并在 trim 后检查重复。
- 确认 Release 包包含 CMS 验证脚本，能在服务器执行项目声明的自检命令。
- 对“new 页面偶发打不开”保存发生时间、浏览器 Console、失败请求 URL/状态码和 Directus 日志；本地正确 Schema 未复现。

## 本轮未执行

- 未修改任何业务代码或测试代码。
- 未对测试站或主站执行写入、迁移、权限调整、部署或发布。
- 未把本地临时 Schema workaround 作为代码修复保留。
