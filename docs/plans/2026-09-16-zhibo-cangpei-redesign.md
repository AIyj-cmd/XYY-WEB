## 当前问题

- 首屏口号过大，副标题远离主标题，长介绍与下方宽幅视频让首屏拉得很长；视频为直角，尚未延续近期页面的浅灰和圆角处理。
- 场次部分同时输出阶段说明、痛点、解决方案、服务描述、指标。相同的爆单、库存和退货信息出现多次，手机端尤其冗长。
- 黑橙柱形装饰不承载实际数据；阶段列表、服务描述、库存链路、侧注、多品牌区域和 FAQ 反复使用边线。
- “场次节奏示意”“接口与字段范围按项目确认”等说明占据主阅读位置；有些限制应保留，但应该换成客户能直接理解的表达。
- 退货混在场后发货中，多品牌方案只有一段说明，重要服务的阅读权重不足。
- 硬编码主标题与 CMS 的 H1 不同。重新设计时应统一服务名称、页面主张和搜索内容的关系，保留自定义内容。

## 设计方向

阅读顺序：直播仓配能解决什么 → 一场直播如何安排 → 库存如何同步 → 退货如何处理 → 多品牌如何管理 → 合作前的问题 → 咨询。

配色延续白色、极浅暖灰 `#F8F8F6`、深黑标题、现有橙色按钮。用留白、字号和背景分组，不添加装饰性横竖分割线。必要的键盘焦点轮廓保留。

- 内容最大宽度约 1280px；桌面侧边留白随窗口变化，手机约 20px。
- 首屏 H1 内服务名称约 30–36px、核心主张约 56–68px；手机约 24px 与 36–42px。标题兼顾大小层级，避免整块同字号加粗。
- H2 桌面约 44–56px、手机约 30–36px；正文 15–16px、常规字重，行高约 1.8。
- 视频及主要背景块圆角约 28–32px，手机约 20–24px。区间距桌面约 88–112px，手机约 56–72px；按内容自然撑开高度。
- 各区使用不同构图：首屏双栏、场次切换面板、库存错落信息、退货横向展开、多品牌开放分组、FAQ 折叠、咨询收尾。
- 当前独立实拍视频继续使用，自动播放、静音、循环、无控制条；保持 16:9，不加遮罩或压在视频上的文案。此次不新增或重复使用仓配总览视频。

## 七个区域

### 01 首屏：先说清楚服务与价值

**标题草案**

直播电商仓配

接住集中订单，
跟上每场直播。

**简介草案**：从开播前备货，到订单发出与退货处理，为品牌自播和代播团队衔接仓内作业。

桌面左侧约 44% 放标题、短简介、浅灰胶囊“品牌自播 / 达人带货 / MCN·代播”和橙色“咨询直播仓配”按钮，右侧约 56% 放圆角视频。浅灰背景覆盖首屏，主张中的一处词语可用橙色，正文保持深灰。

首屏不摆产能、时效、准确率整排数字，也不放长篇接口条件。胶囊表示服务场景，不作为平台授权或接入保证。

手机按标题、简介、胶囊、按钮、视频排列；文字与视频不叠放。只保留一个 H1，服务名称与主张通过 H1 内不同样式形成层级。

### 02 场次安排：页面的主要交互区

**标题**：开播前准备好，出单后跟得上

取消现有柱形装饰和三段长列表。桌面左侧放三个竖排胶囊按钮，右侧一块宽的浅灰圆角内容面板；点击切换阶段。选中项用橙色，小范围淡入约 180ms，无自动轮播，不劫持滚动。

| 阶段     | 面板主张                 | 主要内容                                       | 对应证据                               |
| -------- | ------------------------ | ---------------------------------------------- | -------------------------------------- |
| 开播前   | 货、包材与人手，提前安排 | 场次和预计订单、SKU 与库存核对、包材与人员安排 | 爆单弹性产能；已有实际单仓单日运营峰值 |
| 集中出单 | 订单集中来，仓内有序做   | 订单校验、波次拣货、出库复核                   | 波次分配；不另造每小时产能或实时看板   |
| 发货跟进 | 按约定发货，异常及时跟进 | 截单安排、打包出库、异常跟进与状态回传         | 既有截单及当日发出规则                 |

每个面板由短主张、2–3 项简洁说明、必要指标组成，避免同一能力再叠加“问题＋方案＋介绍”三套文案。峰值标明“实际单仓单日运营峰值”，不写成每场直播的保证产能。

手机将胶囊横排在面板上方，三项均能看见，无横向整页溢出。面板高度随内容变化，不固定高度裁切文字。

交互采用渐进增强：服务内容完整服务端渲染；无 JavaScript 时三阶段按顺序展开；增强后支持方向键、Home/End、Enter/Space、正确的选中状态与面板关联。减少动态效果偏好下取消过渡，不隐藏内容。切换面板的文字不必悬停才能读。

### 03 库存同步：围绕客户要看清的信息

**标题**：多平台出单，库存也要跟上

**简介草案**：连接订单、库存与发货状态，减少多平台卖货时的信息差。

桌面采用左窄右宽的错落布局：左侧放标题和短解释，右侧上方是“订单接入”的宽块，下方并列“库存同步”“发货回传”两个较小块。浅灰底、无连线，以名称和说明表现关系，不模仿后台仪表盘。

库存准确率放在“库存同步”内容附近，并明确它是仓内库存准确率，不等于接口成功率、实时同步速度或零超卖。主流平台协同作为服务范围说明，不再当成一个大数字。

“接入前确认你使用的平台、系统和需要同步的数据”作为简短说明放在区域末尾；具体授权、接口可用性与联调条件归入对应 FAQ。不得无依据添加平台 Logo、毫秒延迟、自动接入或所有平台均适用的承诺。

手机标题在前，三个信息块顺序排列。原 `contentDesc` 的已知重复内容精简；自定义内容保留为本区补充说明。

### 04 退货处理：独立成区，展示商品去向

**标题**：退回来的商品，也有下一步

**简介草案**：拆包核对、质检分级后，根据商品状态安排整理与二次上架。

使用浅灰通栏背景，上方左侧标题、右侧短说明，下方三组开放式内容并列：

- 可售商品：按规则完成复核与二次上架。
- 需要整理的商品：根据质检结果安排整理，需修复的另行评估。
- 异常商品：记录问题并确认后续处理方式。

用小型线性图标和文字层级识别分类，不绘制完整连线流程图，不将质检能力写成独立的直播退货中心。所列是商品处理方向，不是固定质检等级或新增收费套餐。

已有“退货质检与二次上架”时效仅在本区作为一次辅助信息展示，从 claims 读取；保留适用商品与约定服务条件，不扩大为所有瑕疵修复或所有异常都能在该时间内完成。

区域末尾用轻量链接连接“退货质检”“后整修复”详情页。手机按三组自然纵排，不做横向滑动卡片。

### 05 多品牌管理：把机构关心的事情讲具体

**标题**：多品牌一起运营，管理各自清楚

桌面左侧较大标题和“适合 MCN 与代播团队”的短说明，右侧四组开放内容组成两列；用留白分组，不使用边框表格或四个一模一样的重卡片。

| 客户关心的事 | 展示内容                       |
| ------------ | ------------------------------ |
| 商品如何分开 | 按品牌分区管理货品             |
| 账号能看什么 | 按品牌配置库存和订单查看权限   |
| 出库与对账   | 品牌独立出库单与报表           |
| 如何结算     | 可沟通统一结算或各品牌分别结算 |

具体配置结合品牌数量、SKU 和管理需求说明，不暗示新建业务平台、虚构客户案例或必然支持所有系统。手机单列阅读，短标题直接对应说明。

### 06 常见问题：把条件放在需要它的位置

**标题**：开始合作前，你可能还想了解

桌面左侧标题、右侧五个浅灰圆角折叠项；手机上下排列。取消通栏细线，保留原生可键盘展开能力。

| 问题                               | 回答重点                                                       |
| ---------------------------------- | -------------------------------------------------------------- |
| 直播仓配和普通电商仓配有什么不同？ | 订单集中、库存信息、退货衔接三个差异；删去对普通仓的绝对化描述 |
| 支持哪些平台和系统对接？           | 订单、库存、发货与退货数据范围；明确授权、接口及联调条件       |
| 大场直播前，需要提前准备什么？     | 场次、预计订单、SKU、包材与发货要求；峰值不等于单次保障承诺    |
| 如何降低超卖风险，异常怎么处理？   | 同步、校验、预警与跟进；避免“彻底杜绝超卖”                     |
| MCN 或代播机构能否管理多个品牌？   | 分区、权限、报表、结算与具体配置                               |

沿用现有五条 FAQ 的内容身份及对应主题，已知旧文案适当改写；自定义问答原样保留。FAQ 正文与 FAQ Schema 使用同一份最终数据。

### 07 咨询收尾：给客户一个容易开始的动作

**标题**：下一场直播，提前把仓配安排好

**说明草案**：告诉我们开播时间、预计订单、商品种类和平台，一起安排备货与发货。

独立白底区域，横向排标题和橙色“咨询直播仓配”按钮，下方两条轻量链接“查看合作案例”“查看全部仓配服务”。手机纵排。沿用 `/contact`，不新增表单或自动提交。
