## 设计定位

以“华南仓库与仓储服务”作为页面主线，依次回答：仓库分布在哪里、货品如何入库和发货、退货怎样处理、时间怎么确认、启动前需要准备什么。

沿用白底、黑色大标题、橙色按钮和少量细分隔线。主要视觉内容是仓内实拍、四地仓库展示和仓内作业流程；各区域采用不同构图，形成清楚的阅读节奏。

用户已明确：广州、东莞、佛山、肇庆展示的就是仓库，没有“主节点、区域协同、平台协同、制造协同”的分工或层级。此纠正覆盖旧稿中“各有协同重点”等设定。仓库按同一层级介绍，不再以城市推断角色、货物汇总关系或专属业务；也不据此声称各仓库具备完全相同的全部服务。既有文案中与这项纠正冲突的称呼与职责描述需要一起修订，不能以保留旧文案为由继续展示错误定位。

用户已补充[仓库名称与地址资料](2026-09-15-warehouse-addresses.md)。其中广州、东莞、佛山、肇庆对应9条仓库资料，分别为3、4、1、1条；昆山、上海、合肥的3条另行留存。本页仓库分布据此改为按城市分组的仓名与地址清单，具体资料见该文档。清单条数仅用于组织版式，不作为新增经营统计。

## 当前页面分析

已查看本地1440×900和390×844页面、节点区截图及当前South专属源码。当前主体约4850px高，含首屏、区域节点、业务与资源协同、时效说明、FAQ及咨询五个大块。

1. 首屏标题和橙色长句占据较大面积，区域名称在小标题、H1附近、城市行和正文中多次出现。手机首屏在看到视频前需读较长说明，且首屏缺少咨询入口。
2. 区域示意图占据较大空间，信息主要是四个城市和连接线；启用脚本后只显示一个城市的资料，读者比较其余城市需要反复切换。
3. “业务入口”和“资源确认”合计约1704px，大部分内容是连续的文字行；货源、库存、出库、退货之间的关系没有形成直观的主体画面。
4. 发出时间与到达参考混在长段落里，数值与适用条件不容易同时扫描。FAQ之后的咨询区留白较长，收尾松散。

目前两个检查视口没有观察到整页横向溢出。本轮针对信息组织与排版重新设计。

## 新版六区域

### 01 区域片头：完整标题＋实拍与介绍

- 上方用横向大标题交代“华南鞋服云仓”及广州、东莞、佛山、肇庆的区域范围。H1承接解析后的原服务标题，城市说明以较小字号区分层级，全部使用黑色正文体系。
- 下方采用约8:4的不对称布局：左侧为较大的16:9仓内视频，右侧为服务说明、副标题和橙色“咨询华南仓储服务”按钮。
- 使用现有穿品牌工衣的仓内拣货视频。文字放在视频外部；视频保留静音、自动循环、无控制条的播放方式。
- 原`heroDesc`完整保留在说明栏，调整行宽与段落间距；不另造一段重复的橙色大口号。首屏新增咨询入口，但不新增表单。
- 手机顺序：标题与副标题 → 咨询入口 → 视频 → 完整介绍。用网格区域处理桌面位置，保持合理的DOM与键盘顺序。

### 02 仓库分布：按城市展开具体仓名与地址

建议标题：**华南仓库分布。**

- 桌面采用四个纵向城市分组：每组左侧是城市大字，右侧为仓库名称与地址清单。广州、东莞的仓库清单在右侧排两列；佛山、肇庆各自的单条地址占右侧完整行宽。城市之间使用细分隔线与留白，同组仓名及地址对齐；不再用四个等宽长列容纳数量不等的仓库。
- 广州组：黄埔仓、兴泰仓（番禺仓）、新塘仓；东莞组：智谷仓、朗州仓、桥头仓、云谷仓；佛山组：宏盛仓（佛山仓）；肇庆组：四会仓（肇庆仓）。仓名和别名按用户原文展示，地址在仓名下方以较小字号自然换行，默认全部可读。
- 新塘仓、云谷仓仅在地址位置显示“暂不公布”，不生成地图或导航入口，不猜测、搜索或补全地址。其他地址也按用户原文保留，不因设计调整改写地名或推定坐标。
- 昆山花桥仓、上海青浦仓、合肥联亚仓（合肥仓）保留在地址资料文档中，不加入本页华南分组；本轮不修改其他页面。
- 移除主节点、制造协同、区域协同、平台协同等标签及依赖这些定位的说明。各仓库使用相同字级和信息层级；地址中的城市、工业园或物流园名称不用于推导专属角色。
- 仓网统计放在区域标题附近的紧凑信息条，继续使用现有解析字段与限定说明，明确其华南区域口径；不把区域统计附到某一城市，或推导单仓面积、固定仓容。
- 四个城市的内容各有一个落点，展示称呼统一为仓库。与用户纠正不冲突的已确认信息和适用条件保留；不再为了形成四种不同标签而把制造、平台等业务分配给某座仓库。可确认的具体服务放在仓储服务区说明。
- 城市分组与地址清单是静态内容，无隐藏详情、悬停才能看到的文字或无目标点击行为。不新增地图、定位图标或仓库照片来暗示未经核验的实际位置与场景。
- 平板按可用行宽将仓库列表改为单列；手机将城市名称放在该组上方，广州→东莞→佛山→肇庆依次展开。仓名与地址不拆组，长地址不省略、不裁切、不横向滚动。

### 03 仓储作业：从入库到发货

建议标题：**从货品入库，到订单发出。**

- 用一张基于HTML/SVG的流程图作为主体：到货验收 → 入库上架 → 库存管理 → 拣货复核 → 打包发货。只表达仓内作业顺序，不绘制仓库之间的调度层级，也不赋予四地仓库不同身份。
- 下方画出独立的退货回流支路：区域退货 → 质检及按需后整 → 按确认标准进入后续库存与履约。标明是业务关系示意，不表达实际运输线路或地理位置。
- 原货源入仓与退货处理的有效信息放在对应环节说明；“广州主仓”等带层级的称呼按用户纠正改为仓库，不延续主节点或跨仓汇总定位。现有时效、适用条件不因排版改成无条件承诺。
- 原“全渠道”统计与B2C/B2B/退货处理说明融入发货及退货部分。平台业务如有确认资料，在服务说明中单独介绍，不作为肇庆等城市仓库的身份标签，也不暗示所有仓库都无条件支持。
- 关系图不以箭头代替说明文字，全部业务内容使用可索引的真实文本。各列只有必要的边界和连线，避免构成多个重复的信息卡片。
- 手机按入库→库存→拣货→发货→退货处理纵向阅读；连接线重排为单列逻辑，不缩小整个桌面图，也不产生内部横向滚动。

### 04 时效说明：分别说明发出与到达

建议标题：**什么时候发出，预计什么时候到达。**

- 采用浅灰底横向信息区域。左侧为仓内截单与发出的时间轴，右侧为广州同城、广东主要区域、华南主要城市的运输参考说明。
- 左侧依照现有解析统计和审核claims展示截单、当日发出及适用条件；右侧保留当前运输参考中的“最快”“参考”和线路SLA等限定。
- 原`contentDesc`全文保留在本区作为完整说明；已经在其他区域出现的统计不再重复制作大字卡片。
- 不将“当日发出”表达为“当日送达”，不将参考运输时间变成所有订单的无条件保证。
- 运输参考若没有可靠的结构化字段，保留当前解析段落，不从任意CMS自由文本推算时效，也不以硬编码旧值覆盖后续CMS变化。
- 手机先显示仓内时间，再显示运输说明，两部分标签明显、条件跟随对应内容，不做窄屏双列。

### 05 方案确认：让准备信息对应实施安排

建议标题：**让仓容、人力、物流和系统跟上你的业务。**

- 左侧为短标题和准备说明，右侧为四条开放的信息行，每行清楚对应“需要提供的信息”和“方案要确认的安排”。
- 仓容：SKU、库存深度与业务类型 → 实际启用仓点与库存分布。
- 人力：日常订单与活动预测 → 班次及弹性资源。
- 物流：订单目的地、渠道及线路条件 → 承运安排与SLA。
- 系统：订单、库存、作业与退货状态 → 项目系统方案及对接安排。
- 四项准备信息保留，用“仓容安排、人力安排、物流安排、系统对接”表述。原说明中的“各节点”等称呼改为仓库，不补充城市之间的特殊分工，也不重复上一块的运输段落。
- 这是可读的准备清单，不设计成没有提交能力的假表单，也不加入自动选仓或自动报价承诺。
- 手机改为每条上下排列，信息标题与说明始终在同一组内。

### 06 FAQ与咨询收尾

- 原五条FAQ保持原顺序和完整问答，采用原生`details/summary`，无脚本也可以展开。
- FAQ位于居中的适中行宽内容区；下方另用一条横向咨询区收尾：左侧短句，右侧橙色按钮。手机上下排列。
- 保留`/contact`、`/cases`、`/product`等既有链接；末尾不再保留大段空白后才出现的窄咨询栏。
- 不采用额外的弹窗、悬浮表单或页面内多层滚动。

## 排版与交互标准

- 桌面保留全站容器与导航，使用12列网格组织上述构图。H1主要字级约64–88px，H2约36–48px，正文16–18px；所有字号随空间自适应，完整CMS标题过长时自然换行。
- 手机H1约34–40px，H2约28–32px，正文不低于16px。字级范围是实施起点，最终以360/390px实际断行与可读性为准，不以固定高度裁切文字。
- H1与H2分别设置，不用同一字号覆盖所有标题；不出现孤字末行、图文覆盖或导航压住锚点标题。
- 背景以白色为主，时效区可用一处浅灰；橙色用于按钮、重点标识与少量关系线。视频和正文上不添加遮罩、玻璃效果或大面积渐变。
- 使用页面自然滚动。城市比较和业务关系图默认静态可读；仅保留真实链接、原生FAQ及适量入场动效。减少动态效果时内容直接可读，不依赖动效才能出现。
- 不新增城市切换器或自定义tab，旧的节点切换脚本随本页退役时核查唯一引用，避免残留无动作控件。
