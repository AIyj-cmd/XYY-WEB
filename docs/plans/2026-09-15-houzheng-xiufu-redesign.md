## 1. 当前页面与需要解决的问题

已查看当前路由、Repair 专属组件、内容与 claims，并实际浏览 1440×900、390×844 两种视口。三张懒加载图片滚入视口、解码后再截图，不能把首次整页截图未加载的区域当成故障。

- 首屏是左视频、右侧“先评估／再修复／再复检”三段标题。标题表达流程，但具体服务名称处于较小层级；手机先出现视频，随后才是服务介绍。
- 六类异常收在折叠目录中，读者默认只能看到第一项的具体范围；工艺照片、专区名称和验收条件又分别位于后面几个区域，信息联系较弱。
- 工艺图册依次使用大图、右侧小图、通栏大图，说明文字较短。桌面当前该区约 2539px，约占页面主体 6952px 的 37%，阅读距离较长。
- 九专区独立成一块名单，没有与真实工位图一起展示。复检区还重复承担服务总述、流程、结果分流和四项指标，层级较拥挤。
- FAQ 后另设一大段咨询区域，收尾较松散。

这是信息组织与版式调整；当前两种视口均未观察到页面横向溢出。上述尺寸是本次默认展开状态的测量，不是固定高度要求。

## 2. 设计方向

以“商品瑕疵如何处理、处理结果如何确认”为阅读主线，形成一页清晰的修复服务介绍。

视觉重点放在真实操作与有依据的处理条件。大标题负责快速理解，六类服务负责匹配需求，工位图负责展示处理现场，流程和指标负责解释验收。

三个主要构图变化：

1. 首屏采用上方标题与介绍、下方宽幅视频的纵向构图。
2. 六类服务全部展开，工艺展示收敛为一个可切换的主图区域，九专区合并到该区域。
3. 处理流程与能力指标分别设计，最后把 FAQ 和咨询准备事项放在同一收尾区域。

## 3. 页面顺序与版式

### 01 服务开场：服务名称成为第一视觉

**主标题：** 使用 CMS 解析后的服务名称，当前为“服装瑕疵修复与二次上架”。当前中文按语义排为两行，不再将三句流程词作为 H1。CMS 改名或文本变长时自然换行，不能硬编码切字。

桌面上部约 7∶5 分栏：左侧大标题，右侧原服务介绍与橙色“评估修复需求”按钮；下部使用整个内容宽度的实拍视频。让读者先知道服务对象，再看到现场。原 h1sub 保留为介绍中的强调行。

- 内容最大宽度约 1216px；大标题 64–80px，正文 17–18px，行高约 1.75。
- 视频保留目前黑橙工衣的专属镜头与封面，原始 16∶9 展示；1216px 宽时约 684px 高。不强制首屏塞进一屏或裁切为横幅。
- 文字放在白色区域，不叠在视频上，不增加遮罩。视频继续默认静音、循环、行内播放，无控制条。
- 手机顺序为标题 → 介绍 → 按钮 → 视频；文字先交代服务，视频按可用宽度等比缩放。

### 02 六类服务：让客户直接找到自己的问题

**区域标题：** “这批商品，需要处理哪些问题？”

取消当前“左标题、右折叠目录”的结构。改为标题通栏、下方桌面两列三行的开放式服务列表。每项包含小序号、服务名称、完整原描述；用细分隔线和留白区分，不加大圆角卡片、图标或阴影。

按现有业务顺序保留：清污处理、面料修复、缝线修复、配饰修复、鞋类专项修复、标识与异味处理。异常示例及处理限制保留在原描述中，不为了排版截断成一句口号。

- 六项内容直接可见，全部默认展开；桌面每项约 180–230px，允许随内容增高。
- 手机变单列，原描述完整呈现，不做横向滑动、截断或隐藏。
- 该区承担解释服务的职责，不把整块文字做成跳转按钮；区域末尾提供“查看实际工位”锚点。
- CMS 返回的新增、改名、未知服务仍按返回顺序展示，不因固定六格或关键词匹配丢失内容；“六类”仅在默认内容满足该数量时使用。

### 03 专业工位：照片与九专区合成一个区域

**区域标题：** “在对应工位，完成具体处理。”

替换目前纵向交错的三张大图与独立九专区名单。桌面采用约 8∶4 的“主图＋选择目录”：左侧一张约 16∶10 的作业图，右侧三项带小缩略图的工位选择及该图说明。

三个选择严格对应现有真实素材：

| 工位选择 | 展示照片             | 说明重点                               |
| -------- | -------------------- | -------------------------------------- |
| 手工清污 | repair-handwash.webp | 面料特点与处理方式，结果以二次质检为准 |
| 缝补     | repair-stitch.webp   | 处理前确认线色与工艺要求               |
| 手工熨烫 | repair-ironing.webp  | 完成后的状态仍按品牌标准复检           |

点击切换图片、标题和说明，当前项用橙色短线及文字状态标识；默认手工清污。切换不自动轮播，不自动滚动，不改变页面 URL。照片按实际主体设置安全构图；若统一比例会裁掉作业动作，使用原比例或 contain。

主图区下方直接排九个专区名称，小序号＋名称、桌面三列，作为完整能力索引。三个照片入口只是有素材的工位展示，不把六类服务与九专区强行一一对应，不把三张图伪装成九张实拍。

- 手机顺序：区域标题 → 三个工位选择 → 当前图与说明 → 九专区双列；控件可换行且触控高度至少 44px。
- 工位切换支持键盘方向键、Home/End、Enter/Space 和清晰焦点，图片说明通过 aria 关联。
- 无 JS 时自然展开三组图文；九专区始终完整显示。JS 初始化后才增强为切换展示，不能默认隐藏到无法访问。
- 暖灰背景仅用于这个工艺区域，其他主体使用白底。目标桌面主展示约 650–800px，减少当前工艺图册的长距离滚动，实际以图片和文字不裁切为准。

### 04 从评估到交付：把验收条件画清楚

**区域标题：** “修复完成之后，还要通过品牌标准。”

独立展示现有四步工单流程：质检分流 → 工艺评估 → 专区修复 → 二次质检。桌面以一条连续横线连接四个无底色节点，每个节点下方保留具体说明。复检节点下方分出两种处理结果：

- 达到品牌确认标准：进入约定的上架或后续授权流程。
- 未达到确认标准：按约定继续处理或分流。

“结合材质、瑕疵类型及品牌验收规则确认”“关键状态留痕”的原有事实放在对应步骤。流程只是业务说明，不提供自动诊断、预计成功率或虚构修复前后对比。

手机改为左侧连续竖线、右侧逐步说明，末尾上下排列两种去向；不保留横向四列。标题、节点与箭头留出独立空间，不能用绝对定位文字造成覆盖。流程不加自动播放或滚动锁定。

### 05 数据与依据：突出一项结果，解释三项能力

**区域标题：** “修复结果，有明确的统计口径。”

采用左侧大比例数字、右侧三行说明的非对称构图。左侧展示当前修复成功率及完整定义，右侧依次展示可识别缺陷、质检与二次上架整体流程、年退货质检量。原 contentDesc 在该区下方作为服务说明完整呈现一次。

| 当前数据 | 必须保留的口径                                                                           |
| -------- | ---------------------------------------------------------------------------------------- |
| 90%      | 根据公司运营统计；进入修复流程并在二次质检后达到品牌约定上架等级的比例，不作为每批货保证 |
| 135+种   | 可识别鞋服异常类型，不能改成“可修复135+种”                                               |
| 24小时   | 退货质检与二次上架整体流程，不改成每种修复固定时效                                       |
| 1.53亿件 | 年退货质检量，不改成修复量、不虚构统计年份                                               |

上表是当前数据映射，实施时继续从现有解析内容及 claims 取值，不能在展示组件重新写死数字；新增或改名指标要保留。未知指标按原文正常展示，不能误套修复成功率的定义。

手机顺序为成功率及解释 → 三项数据；定义紧跟数字，正文不为了追求数据海报效果变小。数字不做滚动计数动画。

### 06 FAQ 与咨询：在同一区域结束阅读

**区域标题：** “评估之前，先把这些信息准备好。”

桌面左侧约 7 列放现有五个 FAQ，右侧约 5 列放咨询准备清单：商品材质、瑕疵照片、配件情况、品牌验收规则，以及橙色“评估修复需求”按钮。

FAQ 保留原问答内容和原生折叠能力。手机先问答、再清单与按钮。清单只是咨询提示，不新增上传框、表单、资料收集接口或承诺。

保留“了解退货质检”“查看合作案例”“查看全部仓配服务”三个关联入口，并继续使用现有联系页。取消当前 FAQ 下方再隔出一大段咨询区域的安排。

## 4. 整页节奏与响应式

```text
上方：服务大标题                 服务介绍 / 橙色咨询按钮
下方：                  宽幅实拍视频
                          ↓
               六类服务，开放式两列正文
                          ↓
         主工位图                 三项图文选择
                   九专区完整索引
                          ↓
           分流 → 评估 → 修复 → 复检 → 两种去向
                          ↓
         修复成功率与定义          三项支持数据
                          ↓
         五个常见问题              准备清单 / 咨询
```

- 默认内容区最大 1216px，桌面侧边至少 32px；手机 20px。只在后整修复页面作用域实现，不调整全站 shell。
- 桌面区域间距通常 88–112px，手机 56–72px；按内容自然增高，不统一固定区域尺寸，不使用 913×881。
- 层级：H1 桌面 64–80px／手机 36–42px；H2 桌面 40–52px／手机 28–34px；服务标题 22–26px；正文 16–18px、行高 1.7–1.85。
- 1024px 以下首屏和咨询收尾改为上下排；工位展示按实际空间切换为单列；640px 以下服务列表单列、流程纵向。
- 橙色仅用于 CTA、当前工位状态和少量序号。正文维持足够对比，不依赖浅灰小字、文字阴影或背景遮罩。
- 保留现有全站导航、页脚及联系工具；锚点有足够 scroll-margin，兼容固定导航。
- 新增动效仅为工位图切换约 180–240ms、按钮箭头的轻位移；reduced-motion 下取消过渡。没有滚动劫持、鼠标倾斜、闪烁或悬停才出现的关键内容。
